## Phase 3 — Database & providers

- Migration (idempotent, runs at server boot against Supabase): `CREATE EXTENSION IF NOT EXISTS vector`; `documents(id uuid pk, title, source_type, file_name, char_count, chunk_count, created_at)`; `chunks(id uuid pk, document_id fk cascade, chunk_index int, content text, embedding vector(768), tokens int)`; HNSW index (`vector_cosine_ops`); `ALTER TABLE ... ENABLE ROW LEVEL SECURITY` on both tables (the service `postgres` role bypasses RLS, but this blocks reads via Supabase's anon-key REST API).
- `providers/embeddings.ts`: Gemini `gemini-embedding-001` via REST, `outputDimensionality: 768`, `batchEmbedContents` for chunk batches.
- `providers/llm.ts`: Groq OpenAI-compatible endpoint, `llama-3.3-70b-versatile` (env-overridable model names). Both behind small interfaces; `.env.example` documents `GROQ_API_KEY`, `GEMINI_API_KEY`, `DATABASE_URL` (Supabase session pooler, port 5432, sslmode=require), `EMBEDDING_DIM`.

## Phase 4 — Ingestion, retrieval, chat

- **Ingestion**: upload (pdf/md/txt, ≤10 MB) → parse (`unpdf` for PDF; raw for md/txt) → chunk (heading-aware for md, ~900 chars, 150 overlap) → batch embed → insert in a transaction.
- **Retrieval**: embed question → cosine `<=>` top-k (default 5) → similarity = 1 − distance; default threshold 0.30 (tuned via eval).
- **Chat** `POST /api/chat`: retrieve → if no chunk passes threshold, skip the LLM and return a distinct `sufficient: false` response → otherwise prompt LLM with numbered context, require inline `[1]`-style citations mapped to sources. Response: `{answer, sources[{documentTitle, chunkId, score, snippet}], sufficient, timings{embedMs, retrievalMs, llmMs, totalMs}}`.
- **Debug** `POST /api/retrieve`: retrieval-only (no LLM) returning chunks, scores, timings.
- Other routes: `GET/POST/DELETE /api/documents`, `GET /api/health` (checks DB + both providers). Middleware: CORS (localhost:3000), rate limiting, zod validation, multer limits, error handler. Conversation history stays client-side; no agent frameworks.

## Phase 5 — Sample incidents + eval

7 seeded markdown docs: Node.js event-loop blocking · Postgres deadlock · Postgres pool exhaustion · Redis OOM/eviction & cache stampede · Docker container OOM (node heap vs cgroup limits) · Nginx 502 upstream timeouts · WebSocket drops behind proxies. `scripts/eval.ts` computes hit@1 / hit@3 / MRR + threshold sweep against `eval/golden.json` → the "measurable retrieval quality" deliverable.
